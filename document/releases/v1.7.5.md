## Release Note

AndroidBase 1.7.5 adds a Quick foundation for application startup, user state, data migration, and one-time ViewModel initialization. `StandardActivity` can now take configuration for a single launch, and crash reports written by the default handler can be read back for upload or export. Existing `BaseApp`, `BaseUserManager`, and `BaseDataMigrateManager` integrations keep working.

### New APIs

- **Quick foundation** — Adds `QuickApplication`, `QuickUserManager`, `QuickDataMigrateManager`, and `QuickViewModel` for new integrations.
  - `QuickApplication` stores the app name and runs startup initializers, with the same startup behavior as `BaseApp`.
  - `QuickUserManager` keeps the same persisted user id, token, and user info as `BaseUserManager`. `login`, `logout`, `getToken`, and `setToken` are suspend functions and run one at a time, so overlapping updates cannot interleave. Login and profile updates post `UserStateEvent.LOGIN` or `UserStateEvent.UPDATE`. Logout posts `UserStateEvent.LOGOUT`. Observe these events with `AppEvent` instead of the local broadcast actions used by `BaseUserManager`.
  - `QuickDataMigrateManager` starts versioned data migration with the same `base_` data id prefix as `BaseDataMigrateManager`.
  - `QuickViewModel.initialize { }` runs a block at most once per ViewModel instance on a background dispatcher. It is the class-scoped form of the existing `ViewModel.initializeOnce { }` extension, which remains available.
- **`StandardActivityConfig`** — `StandardActivity.open` and `StandardActivity.call` accept an optional configuration that applies only to that launch. `beforeCreate` runs after the launch request is resolved and before the activity calls its parent `onCreate`. `statusBar` and `onInit` override the existing global callbacks for that request when they are set. The previous global `statusBar` and `onInit` callbacks still apply when the request does not set them.
- **Crash report retrieval** — Adds `CrashReportStore.loadCrashReports()`. It returns reports saved by the default crash action under the app cache `crashReport` directory, ordered from newest to oldest. Each `RecordInfo` includes the parsed exception data and the report file, so an app can upload the file and delete it afterward. A file that cannot be read or parsed is skipped. `CrashDefaultActions.saveCrashReportToFile` also accepts an optional target file. A custom file is included by `loadCrashReports()` only when it is inside the default crash report directory.

### Behavior Changes

- **`StandardActivity.open` requires a foreground activity** — `open` now throws `IllegalStateException` when no activity is available. Previously it returned without launching. `call` still fails in that situation, with the message `No Activity available to launch StandardActivity`.
- **Dialog show and dismiss wait until resumed** — `ViewBindingDialogFragment` and `ViewBindingBottomSheetDialogFragment` no longer use the deprecated `launchWhenResumed` API. `show(lifecycleOwner)` and `dismiss()` wait until the owner is resumed, wait 177 milliseconds, then wait until it is resumed again before showing or dismissing. If the owner is destroyed during that wait, the operation is cancelled. Calling `show()` without a lifecycle owner still shows immediately when the fragment manager state has not been saved.

### Breaking Changes

- **`StandardActivity.open` no longer ignores a missing activity** — Callers that invoked `open` before any activity existed, and relied on the silent return, must guard the call or handle `IllegalStateException`.

### Migration Notes

- **Existing integrations can stay on the `Base*` types** — `BaseApp`, `BaseUserManager`, and `BaseDataMigrateManager` are still supported. Move to the Quick types when you want suspend user operations and `AppEvent` user-state notifications. Persisted user data remains readable because `QuickUserManager` uses the same storage keys.
- **If you replace `BaseUserManager` with `QuickUserManager`** — Call `login`, `logout`, `setToken`, and `getToken` from a coroutine. Replace `token` reads and writes with `getToken()` and `setToken()`. Replace local broadcast registration for user login, logout, and update with `AppEvent` collection of `UserStateEvent`.

```kotlin
// Before
userManager.token = token
userManager.login(userInfo)
val currentToken = userManager.token

// After
userManager.setToken(token)
userManager.login(userInfo)
val currentToken = userManager.getToken()
```

- **If Java code calls `saveCrashReportToFile`** — Pass the new `targetFile` argument. Use `null` to keep writing `cache/crashReport/error_{timestamp}.txt`. Kotlin call sites can omit the argument.

### Compatibility

- The library now builds with `compileSdk` 34 and Kotlin 1.9.25. `minSdk` remains 23 and `targetSdk` remains 33. Android Gradle Plugin remains 8.2.2.
- The published API dependency on AndroidWidget moves from 1.7.3 to 1.7.5.

### Known Issues

- **`StandardActivity` launch state stays in memory** — The fragment instance and `StandardActivityConfig` callbacks are not written to the launch intent or saved instance state. After process death, those callbacks are unavailable. If the fragment was not restored by the fragment manager, the page shows `ErrorFragment`. Do not capture an Activity, Fragment, or View in a shared configuration; a shared configuration can live for the whole process.

## Changelog

- Added `QuickApplication`, `QuickUserManager`, `QuickDataMigrateManager`, `QuickViewModel`, and `UserStateEvent` as the Quick foundation API.
- Made `QuickUserManager.login`, `logout`, `getToken`, and `setToken` suspend functions serialized on one coroutine, and published login, logout, and update through `AppEvent`.
- Added `StandardActivityConfig` and optional per-request `beforeCreate`, `statusBar`, and `onInit` callbacks on `StandardActivity.open` and `StandardActivity.call`.
- Stored `StandardActivity` launch requests in a process-local map, removed them when launch or `beforeCreate` fails or when the activity finishes, and required a top activity for both `open` and `call`.
- Added `CrashReportStore.loadCrashReports()` to read default crash reports from newest to oldest, skipping unreadable files.
- Added an optional target file to `CrashDefaultActions.saveCrashReportToFile`. Custom files are listed only when they remain in the default crash report directory.
- Updated `ViewModel.initializeOnce` to the AndroidWidget lambda form of extra storage. Public behavior is unchanged.
- Replaced deprecated `launchWhenResumed` in `ViewBindingDialogFragment` and `ViewBindingBottomSheetDialogFragment` with `lifecycleScope` and `withResumed`, including a second resumed check after the existing delay.
- Updated the build to `compileSdk` 34, Kotlin 1.9.25, and AndroidWidget 1.7.5.
- Sample: switched the application, user manager, and startup ViewModel to the Quick foundation, and observed `UserStateEvent` from the user demo screen.
- Sample: registered per-variant dependency dump tasks that write each variant's compile and runtime classpath to the project root.
